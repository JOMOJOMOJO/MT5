# 複数年取得後の固定検証

2016〜2025年の候補・tick品質を統合する。2016年の失敗はagent journalのローテーションによる保存漏れで、元journalから復旧し再実行しない。元batch statusは履歴として保存する。

生成tickを含む年は候補インベントリに残し、教師あり正解へ昇格させない。2024年82件と2025年213件の計295件で、前回と同じ特徴量・117入力・Logistic/Tree/LightGBMの固定設定を使う。特徴量の追加・削除・閾値探索なし。

2025年を4四半期に分けるexpanding walk-forward：

- 2024年の適格ラベルで学習 → 2025年1〜3月
- 上記＋2025年1〜3月で学習 → 2025年4〜6月
- 上記＋2025年4〜6月で学習 → 2025年7〜9月
- 上記＋2025年7〜9月で学習 → 2025年10〜12月

15分embargo、決済時刻によるpurge、親ID重複排除、train限定の補完/標準化/one-hot、予測確率固定binは維持。過去に検証した2025年期間も含むため、完全未使用OOSとは呼ばない。未来の結果をtrainへ混ぜない時間順の再現性確認として扱う。

モデル・特徴量を結果に合わせて再選択しない。permutationは前処理後の同一列群の入れ替えで高速化し、生入力を入れ替えた予測との一致を確認する。回数20、seed0は維持。モデル自体の学習パラメータは同じ。

各fold成績、集約OOF、確率bin、係数方向、Tree採用回数、LightGBM test importance、M15/H1 group importance、KMeans k=2〜6を保存。追加で決済ベースの価格Rと頻度を報告するが、本番条件へ採用しない。
