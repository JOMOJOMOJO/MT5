# ①内部の往復を見送る切替：Wave33ChopDiagnostic v1.82

ユーザー依頼により、診断専用だった指標を任意の発注フィルターとして使う設定を追加した。元の `Wave33VisualVerifier`、共有エンジン、Fib条件、RR、SL/TP、約定済み取引の決済ルールは変更しない。

## 設定方法

テスターで `dev\\mql\\Experts\\Wave33ChopDiagnostic.ex5` を選び直す。v1.82の入力項目が表示されたら、次を設定する。

| 入力 | 値 | 動作 |
|---|---|---|
| `InpEnableTesterOrders` | true | 過去データのテスター内で発注する |
| `InpSkipChoppyWave1` | **true** | 往復指標0.5以上の①からの発注を見送る |
| `InpSkipChoppyWave1` | false（初期値） | 従来の売買条件を維持する |
| `InpChopDiagnostic` | true | 診断記録を出す。falseでもフィルターONなら根拠記録は継続する |

以下は全入力を含む比較用プリセット。両方ともテスター発注ON、リスク率1%、指標0.5固定。ON/OFF間の戦略入力差はフィルターのみで、実行タグはログ混同を防ぐため別にしている。

- M5×M1：[フィルターON](../../../presets/wave33/Wave33Chop_v182_B_FilterOn.set) / [OFF](../../../presets/wave33/Wave33Chop_v182_B_FilterOff.set)

## 指標の定義

**往復指標 = ①内部の逆行幅の合計 ÷ ①の起点から終点までの値幅。**

①の固定起点 → その期間内部にある確定済み下位足スイング → ①の固定終点を順につなぐ。ロングなら下向きの値動きだけ、ショートなら上向きの値動きだけを足す。

例：ロングの①が `100 → 108 → 102 → 110` の経路なら、下向きは108→102の6。①全体は110−100=10なので、指標は6÷10=**0.6**。フィルターONなら見送る。

- **0.5以上が見送り対象**。0.5未満は、このフィルターでは見送らない。
- これは往復の回数や②のFib押し率ではない。何度も戻れば1.0を超える場合もある。
- M15×M5では①内部のM5確定スイング、M5×M1ではM1確定スイングを使う。初期値は左右2本の確認を待つ。
- 同種の高値・安値が連続する場合は、その区間の最も高い高値／最も低い安値へ整理する。
- 判定はシグナル時点で知り得たスイングだけ。同じ時刻でも、シグナルより後のイベントは使わない。形成途中の足や、後から確定したスイングを追加しない。
- ②やエントリー後の往復は含めない。①の起点・終点の認識も変更しない。

直前のユーザー画像に対応する保存済み2月9日の例は、①幅6.07・内部逆行合計5.61なので、5.61÷6.07≈**0.924**。同じシグナルと既知スイングが成立すれば、フィルターONで見送りになる。実際の全期間のON/OFFでは、候補を終了して次の波を探すことによって後続候補も変わり得るため、旧約定一覧からの単純な差引を新成績とは扱わない。

## 見送りと判定不可

ONでCHOPPYと判定した場合、OrderCheck/OrderSendより前に処理を終了する。`SKIP / EXCLUSION / CHOPPY_WAVE1` を記録し、チャートには「見送り: ①内部の往復が多い」を表示する。見送り候補に緑のENTRYを描かない。方向の監視枠を解放し、同じセットアップIDを後で発注しない。

履歴不足、同一元足の高安両方が確定して足内順序が不明などで `UNAVAILABLE` なら、このフィルターでは除外しない。`ALLOW_UNAVAILABLE` と理由を記録し、他の従来条件で判断する。判定不可を指標0として解釈する処理はない。

根拠は `<実行タグ>_chop.csv` と従来のevents CSVに保存する。新しい `CHOP_ENTRY_FILTER` イベントに指標、閾値、①価格・元足時刻・既知時刻、評価時刻、フィルター設定、ALLOW/SKIPを記録する。`entry_filter_enabled` 列も実際の設定を反映する。CSVのヘッダー・各診断行を即時フラッシュし、テスター実行中にも読み取れるようにした。
