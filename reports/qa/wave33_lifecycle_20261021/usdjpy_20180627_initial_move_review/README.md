## 前の6月7日と違う点

08:45時点で既知の直近2高値・2安値は次の通り。

|種類|前の足 / 価格|後の足 / 価格|価格関係|
|---|---|---|---|
|高値|07:35 / 110.001|08:00 / 110.007|切り上げ|
|安値|06:55 / 109.865|08:30 / 109.907|切り上げ|

価格関係はHH/HLだが、時刻順が **安値06:55 → 高値07:35 → 高値08:00 → 安値08:30**。現行CounterPivotsは最新の2高値・2安値をそのまま使い、H-L-H-LかL-H-L-Hの交互順序も要求する。この4点はL-H-H-Lなので、上昇調整を認定しない。高値が連続したときの整理がなく、目視でひと続きの戻りに見える形を拾えていない。

08:15以前は安値06:25の109.885 → 06:55の109.865が切り下げ。09:15には安値08:30の109.907 → 09:00の109.832が切り下げになる。その後の高値09:25の109.938は08:00の110.007より低い。結局、必要な4点は一度も成立せず、10:10にW1安値109.770を終値109.759で割った時点で候補が終了した。

[6月7日](../usdjpy_20180607_initial_move_review/README.md)の「高値更新時も安値が切り下がる」例とは違い、今回は**価格が両方切り上がった時でも、並び順の条件で通らない**例として保持する。W2所属チェックより前で不成立のため、v1.30の新しい価格一致条件を解除しても、この直接原因は変わらない。

## 見直しの候補と限界

連続する同じ側のpivotを既知時点で整理し、ひと続きの戻りとして認定する案は比較対象になる。一方、単に交互順序の条件だけを削除すると、異なる局所波を混ぜる可能性がある。W2への所属・初動後の使い回し防止は別に保つ。

08:30安値109.907は08:45に初めて確定する。これを使って08:30や08:35に過去注文が出せたとは扱わない。現行の既知時刻ルールを保つなら、最も早い検査足は08:45開始・08:50確定で、実際に終値突破したかを別に確認する必要がある。今回は新しい認定法や注文時刻のシミュレーションは行っていない。

画像のどの足に入ってほしいかは未指定であり、理想エントリー位置を確定したという意味ではない。EA・入力・終了条件は変更しない。ユーザーが良いとした見送り・4月26日の買いも比較対象に残す。
