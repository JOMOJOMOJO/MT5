# 9月6日・9月17日：紫の抵抗とW1高値までの余地

ユーザーは「抵抗の基準は何か。第1波高値に近いところで買い、その高値を超えられず逆行しているように見える」と質問した。画像2件をv1.30の実CSV・元pivot・コードへ照合。今回は説明と証拠保存のみで、EA・設定・稼働中テスターは変更していない。

## 実際の価格

時刻はテスターのブローカー／元データ時刻。Rは当該買値から初期SLまでの価格幅を1とする。

|項目|画像1：2018.09.06|画像2：2018.09.17|
|---|---:|---:|
|買い時刻|11:55|16:20|
|買値|111.398|112.074|
|W1高値|111.419|112.083|
|W1高値までの余地|0.021円 / 0.12805R|0.009円 / 0.05233R|
|初期SL|111.234|111.902|
|初期TP|111.562|112.246|
|紫の抵抗候補|111.399|112.075|
|抵抗候補までの余地|0.001円 / 0.00610R|0.001円 / 0.00581R|
|抵抗候補の出所|7/23 22:20のM5安値（HL）|9/14 17:30のM5高値（HH）|
|そのpivotが既知になった時刻|7/23 22:35|9/14 17:45|

両方ともW1高値より下で買い、TPはW1高値より上にある。この位置関係は確認できる。一方、紫の抵抗候補は当該W1高値そのものではない。下落の因果を抵抗への反応だけで証明したわけではなく、相場全体の統計的な比較は行っていない。

## 現行コードの基準

[GetObstacles / InspectObstacle](../../../../mql/Include/Wave33Visual/Engine.mqh)、[Obstacle / Plan](../../../../mql/Experts/Wave33VisualVerifier.mq5)を確認。

1. 当時までに確定して保存したM5・M15・H1のスイング高値・安値を候補にする。W1高値も候補に加える。
2. LONGは実際の買値より上で価格差が最小の水準、SHORTは売値より下で価格差が最小の水準を選ぶ。既知時刻が判断時点より後のpivotは使わない。
3. 高値だけ・当日の高安だけには限定しない。古さ、過去の突破による失効、反発回数、重要度、価格帯のまとまりも選別していない。9月6日の例は、過去の押し安値を価格が上にあるため抵抗候補として選んでいる。
4. したがって表示名「抵抗」は、正確には「進行方向にある最も近い既知のスイング価格候補」である。現在有効な重要抵抗だと判定した表示ではない。

表示はSIGNAL/RISK_CHECK時に採用候補を更新し、エントリー付近へラベルを置く。紫ラベルがENTRYと近いことは、抵抗への到達を入口としている意味ではない。

## なぜ近くても買うか

設定は `obstacle_mode=DISPLAY_ONLY`。下位転換でシグナルを出し、SLはW2極値の外、TPはSL幅×RR1で算出する。抵抗の近さによる見送りもTP短縮も行わない。W1高値の再突破も必須にしていない。したがって、この2件ではW1高値を上回る進行がなければ目標TPには届かない注文を許す。

実装済みのSKIP_IF_BLOCKEDは最寄り候補まで目標RRの余地がなければ見送り、CAP_TPは候補の手前へTPを縮める。ただし現在の粗い抵抗候補をそのまま使うと、古い小さな高安の影響が強くなる。今回の画像だけでいずれかのモードを採用・検証済みとはしない。

## 今後の比較に残す課題

「W1高値までの余地」と「過去の抵抗候補」を区別し、採用された水準の出所・現在の意味を表示する必要がある。W1直下の入口をどう扱うかは、先の良い買い・売りと対比する。[ユーザーが良いとした事例](../usdjpy_20180905_good_case_review/README.md)。一律の除外を追加して初動をさらに減らす前に、抵抗候補の選定を整理する。

同じ選定の限界は [2016年5月16日の抵抗レビュー](../../wave33_visual_20261020/usdjpy_20160516_resistance_review/README.md)でも観測した。v1.30は波の所属・候補寿命の修正であり、抵抗選定の改善は含んでいない。
