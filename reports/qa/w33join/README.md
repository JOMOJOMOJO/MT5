# 接続する逆方向①：発注前に止められる時刻

2026-10-23にユーザーが提示した画像を、直近のCommon CSVと照合した。XAUUSD+、2023.01.05、M5×M1、EA v1.71。タグ名は旧v1.61 SET由来だが、設定CSVの実EA版は1.71。EA変更や追加バックテストは行っていない。

|出来事|ブローカー時刻|
|---|---|
|元のショート①の安値となる足|17:35、1825.03|
|ショート①の終点が確定して既知になる|17:50|
|同じ17:35・1825.03を起点とするロング①候補が発生|18:10|
|元ショートの発注|18:25:00|
|元ショートの実約定|18:25:07|
|ロング①終点の足位置|18:15|
|ロング①の終点が確定して既知になる|18:30|
|元ショートが逆①後の利益決済待機に入る|18:30|
|元ショートがSL決済|19:09:30|

画像ではロングの青①が18:15の足へ描かれるが、EAがその確定を知ったのは18:30。18:25の注文へ、18:30の確定情報を遡って適用することはできない。既約定を消す場合も、取引の取消ではなく決済ルールの変更となる。

この事例を未来情報なしで見送ること自体は可能。**元ショートの確定①終点を共有する、新しい逆方向の①候補が18:10に発生した時点で、未発注の元ショート候補を無効化する**という条件なら間に合う。反対①の確定を待つ条件ではこの事例は止められない。

これは現在の「約定後に反対の青①が確定したら、推定費用込みでプラスの最初の実行可能tickで決済」と別の新規見送り条件。候補段階で止める場合は、反対候補が後で失効するケースも旧方向を見送る。改善効果は未検証なので、今回の一例から年間改善と断定しない。コード・RR・既存利益決済は維持し、見送り条件はまだ実装していない。
