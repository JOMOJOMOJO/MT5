ユーザー画像の買いを実CSVと照合した。01:55の売り事例とは別の、05-16 14:30のLONG。表示M5、判定M15×M5、PIVOT_BREAK、抵抗DISPLAY_ONLY。元テスト・入力・コードは変更していない。時刻は元のテスターブローカー時刻。

実装は下位転換を入口としてシグナルを発行し、取引計画時に進行方向の最寄りスイング水準を探索する。抵抗への到達をシグナル条件にする処理はない。DISPLAY_ONLYでは近さを記録・表示するだけなので、結果的に抵抗候補の直下でも買う。

画面の「抵抗」はSIGNAL/RISK_CHECK時に選んだ水準をエントリー付近の横位置へ出すため、緑ENTRYと重なりやすい。表示位置が発注条件を意味するものではない。

## 抵抗候補の品質は別の確認が必要

108.905の元データは04-13 05:30のM15高値（HH）、確定を知った時刻は04-13 06:15。目の前の高値だけを選んだものではない。現実装は蓄積した確定高安を全て候補にし、古さ・反応回数・重要度・突破後の無効化を選別しない。一般にLONG候補でも高値だけを集めているわけではなく、進行方向側の高安価格を拾う。従って画面の表示は「既知の水平水準候補」であり、有効な重要抵抗を証明したものではない。

既存SKIP_IF_BLOCKEDは、候補までの距離Rが目標RR未満ならOBSTACLE_NEARで見送る。当該スナップショットは0.00687R < 1.0Rなので対象となる。ただし今回そのモードで通期再実行はしていない。CAP_TPは抵抗手前へTPを縮め、利益側にTPを置けなければ見送る。

初版仕様は抵抗を理由とした暗黙の除外を避け、まず表示・ログで採用候補を照合する設計だった。モードを一律に変える前に、何を重要抵抗と呼ぶかを目視と合わせる必要がある。今回も自動的な条件追加・最適化は行っていない。
