# USDJPY 2016-01-25：希望08:03と実約定08:15の差

ユーザーが自身のビジュアルバックテスト画像で、08:03付近で買いたかったと指摘した。元の稼働中テストCSV・設定を読み取り、当該セットアップと時刻の窓だけを保存した。テストの停止、設定変更、再実行、コード変更は行っていない。時刻は元のテスターブローカー時刻。

## 確認できた理由

[設定](source_config.csv)はUSDJPY、表示M1、**判定M15×M5**、PIVOT_BREAK、左右2本、発注ON。チャートの表示時間足をM1にしても、EA内部の下位判定時間足M5は変わらない。

|時刻|その時点で確認したこと|
|---|---|
|07:55|M5の逆方向構造が確定。戻り高値の突破判定線は118.727。|
|08:00|当該候補のトレンドライン突破を診断記録。採用中のPIVOT_BREAKとは別の観測。|
|08:03|08:00～08:05のM5足の形成途中。現行のM5確定終値による新規シグナルの時刻にはならない。|
|08:15|08:10開始のM5足が閉じ、終値118.804でPIVOT_TRIGGER。発注・約定は118.813。|

W1の終点は04:15の118.852、確定を知った時刻は05:00。W2極値は07:40の118.607、観測は07:45。Fib到達は05:55に既知。この事例の08:03→08:15の差は、上位終点やFibが08:15まで未確定だったためではない。既知のM5戻り高値に対する確定終値突破を採用した結果である。

証拠：[当該セットアップの元イベント](setup_events.csv)、[07:15～08:20の全イベント](window_events.csv)、[主要時刻一覧](timeline.csv)、[読取条件](provenance.json)。画像のW2約118.607、ENTRY約118.813、SL118.588とも整合する。

## 変更する場合に分けること

MT5/MQL5で08:03付近の注文を実装すること自体は可能。ただし現行のM5終値確認を維持すると、その時刻の注文にはならない。上位M15の波を維持し、下位のエントリー確認だけM1にする入口や、既知のM5水準の足内突破を使う入口は別の仕様になる。

08:03開始のM1足の終値を確認するのは08:04以降。08:03時点で発注するには、08:02足までの確定情報で条件が揃うか、明示的な足内突破が必要。当該08:03のM1バー・実ティックは今回は取得していないため、その時刻に提案方式が成立したとは断定しない。

単にパターンB（M5×M1）へ変更すると上位の波も変わる。SwingRight=1も上下足・H1等のスイング全体を変えるため、希望時刻だけを早める操作として扱わない。トレンドライン診断08:00は別方式の手掛かりだが、モードを変更した通期再実行でも同じ候補・約定になる保証ではない。今回は認識差を説明する段階とし、ロジックは変更していない。
