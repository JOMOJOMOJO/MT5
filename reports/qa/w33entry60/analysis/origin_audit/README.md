# 青い①の起点を越す途中の極値：後から追加した工学監査

画像の勝敗を開示する前に、担当者が V030/V036/V041/V054 の青い①の中に、起点より低い値があることを指摘した。この検査は元の 5 項目とは別の、**画像観察後に追加した意味・描画の監査**。新しい入口条件の事前登録試験として扱わない。元のパケット・5 特徴・注釈を変更していない。

ORDER 時点で既知の上位足について、①起点足より後、固定終点足より前の足を検査した。LONG は安値が起点より半ポイント超低い、SHORT は高値が起点より半ポイント超高い場合に計測する。終点足だけで起点側の極値も更新している例は分けた。終点足の中で高安のどちらが先だったかは OHLC から分からない。

## 勝敗開示前に固定した計測

| 対象 | 件数 |
|---|---:|
| 年間完結取引 | 440 |
| 起点〜終点の厳密な内側の足で起点を逆側へ突破 | 37 |
| その最初の足がブレイク足より前 | 35 |
| その最初の足がブレイク足そのもの | 2 |
| その最初の足がブレイク足より後 | 0 |
| 終点足だけで起点側を突破 | 1 |
| 起点価格が元上位足の極値と一致しない | 0 |
| 終点価格が元上位足の極値と一致しない | 0 |

全 ORDER の上位足と、原本足 CSV の時間足・設定時間足も一致した（`source_tf_check.json`）。37 件の内訳は A 7 件、B 30 件、LONG 16 件、SHORT 21 件。

4 つの画像例はすべて B・LONG で、最初の起点割れの足がブレイク足より前に存在した。元足と実際に終値が既知になった時刻は `origins_all.csv` に分けて保存。ここでの `known_at` は **OHLC が既知になった時刻**であり、その足が左右 2 本の確定スイングになった時刻とは別である。既知の極値と確定スイングを同一視して、EA のバグと即断しない。

V030/V036/V041 は負け、V054 は勝ちだった。少数の負け例だけなら問題に見えるが、年間では A/B が逆方向。この旗を一律に除外する収益根拠は得ていない。元の①起点の選び方と表示の意味を説明・監査する項目として残す。

勝敗開示前の原本・計測は `manifest.json`、開示後の対応・集計は `outcomes/manifest.json` に分離した。どちらも同じ 2020 年のサンプル内資料。EA・注文条件・テスターは変更していない。
