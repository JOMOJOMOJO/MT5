# 1月の負けはどの経路で起きたか

確認できた直接の負け方は、**利確開始の+1Rに届かず、元のSLで終わる取引が大半だった**こと。利益を大きく伸ばしてから吐き出す負けが、1月の主因とはいえない。

|集計|取引数|負け数|負けのうち+1R未到達|負けのうち+1R到達|
|---|---:|---:|---:|---:|
|OFF全体|29|21|20|1|
|OFF LONG|13|8|8|0|
|OFF SHORT|16|13|12|1|
|ON全体|16|11|11|0|
|ON LONG|7|4|4|0|
|ON SHORT|9|7|7|0|

ONで残った負けショート7件は、有利に動いた最大幅の中央値が0.058R、最大でも0.512R。1Rでの部分利確や、1.5RからのSL引き上げを調整しても、この7件はその開始水準に届いていない。

唯一+1Rに達してから負けたのは、OFFの1月8日14:17のショート。最大+1.452Rまで動き、1Rで半分を利確した後、残りが元のSLに戻り、コスト込み−0.0304Rとなった。これと、ほぼ−1Rの初期SL損失20件を分けて考える。

## MFEの定義・信頼性の確認

今回の`max_favorable_r_logged`は、実際の平均約定価格から、ロングはBid、ショートはAskが有利に動いた幅を、固定した当初SL幅で割った値の最大。形成途中のH1やM1高安を後から足した数字ではなく、EAがnative OnTickで処理した実行側気配値の記録。

凍結済みソースの`W33ObserveDayTradeQuote`が最大値を更新し、`ManageDayTradeStops`は注文保留等のSL変更ガードを評価する前に観測する。全45ポジションで初回約定ティックに状態が初期化され、実際の約定価格・元SL・固定リスク幅が一致。記録最大値は単調非減少で、最終daytrade行とpositions.csvも一致した。

さらに、+1R到達のID集合が、別の部分利確観測・約定イベントおよびraw約定の部分決済フラグと完全一致（OFF8件、ON5件）。部分利確の拒否・利用不能・待機の記録は0件。+1R未到達の負けではSL段階が−1のままで、観測されたブローカーSLは元SL、部分利確なし、終了理由はSLだった。

この整合確認は「EAが処理したnative気配値で+1Rに達したか」の分類を支える。全ティックを独立エクスポートして得た理論上の最大値とまでは呼ばない。時間・逆①決済はMFE観測より先に処理され、ブローカーSLもOnTickより先に約定する場合がある。値幅RのMFEには実行Bid/Askを通じたスプレッドは反映するが、手数料・スワップ等は含まない。最終損益Rには全コストを含む。

元CSVの自由文reasonに未引用セミコロンがあるため、daytradeとpartialをヘッダー末尾の固定型列数から復元してから照合した。通常のpandas読み込みの列ずれを根拠にしていない。

## 根本原因として、まだ言い切れないこと

今回のH1フィルタが13件（10敗・3勝）を除外し、共通16件の実行・損益Rを変えずに損失を減らしたことは確認済み。しかし、それだけで「全てH1レンジでの転換誤認」「エントリーが遅い」「SLが広すぎる」「ダブルトップ」が根本原因とまでは判定できない。H1のERは終値経路の相殺率であり、反転回数・方向・ヒゲを直接測らない。

特にショートは、OFF平均−0.5817Rに対し、ON平均−0.5867Rと改善していない。H1の往復度だけでショートの失敗を十分に選別できたとはいえない。1月で確認できたのは、問題の中心が「伸びた後の利確位置」よりも「所定の利確幅に進めないエントリー」にあるという損失経路。原因候補の優先順位を上げる材料であり、未見月の有効性や唯一の原因の証明ではない。
