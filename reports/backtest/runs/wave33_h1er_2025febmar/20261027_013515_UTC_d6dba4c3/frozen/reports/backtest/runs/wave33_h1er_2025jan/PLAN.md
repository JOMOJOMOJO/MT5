# H1往復度：固定条件一つのOFF/ON比較

2026-10-27。ユーザー指定は「H1の往復度を一つだけ比較」「定義をじっくり確認」。本計画は金 XAUUSD+、M5×M1、2025年1月に限定する。採用、最適化、年間拡張、実口座注文は行わない。

## 定義

注文判断時点で確定済みの、古い順のH1終値13個を C0…C12 とする。

- net = abs(C12 − C0)
- path = Σ(i=1…12) abs(Ci − C(i−1))
- ER12 = net / path
- 往復度 = 1 − ER12
- ONのみ ER12 ≤ 0.25、すなわち往復度 ≥ 0.75 を見送る。

往復度は終値の経路の相殺度であり、反転回数、ヒゲの多さ、ダブルトップ、将来の方向や負け確率ではない。単調な上昇・下降はER=1/往復度=0、出発点に戻る経路はER=0/往復度=1。一回のV字でも多数の細かな往復でも同じ値になり得る。上昇移動合計U、下降移動合計Dなら、往復度=2×min(U,D)/(U+D)。0.75は「75%の足が逆行」という意味ではない。

今回の測定版は `NATIVE_H1_CLOSED_ER12_025_V1`。CopyRates(PERIOD_H1, shift=1, count=13)、全バーの開始時刻+3600秒≤判断時刻を検査する。13本の観測バーを使用し、週末・休場をまたいだ窓を連続12実時間と呼ばない。窓の時刻、価格、経過秒数、ギャップ数を全件保存する。ギャップによる追加見送りは入れない。

履歴不足、非数、未来・形成中の足、不正な時刻、path=0はUNAVAILABLEとして記録し、除外条件を追加しない。ER=0に補完しない。境界の浮動小数点誤差だけを1e-12で補正する。閾値探索はしない。

## 先行診断と実施理由

[保存済み取引の固定比較](../../analysis/wave33_h1_er_compare_20261027/offline/README.md)は旧M5履歴から作る `observed_complete_m5_H1_proxy`。金v1.90の1月は23→13件、合計−9.499→−2.312R。一方、USDJPYの2月では−0.733→−1.160Rに悪化し、金v1.80ではPFも改善していない。旧版・部分月・既に探索したデータであり、独立したOOS検証ではない。

独立レビューはこの不整合から実機実験を見送ることを推奨した。実行担当は、今回の明示的な比較依頼に対し「現在のv1.91決済を固定した、1か月・2アームの限定診断」まで実施する判断とした。救済の閾値探索や一般採用には進まない。先行診断は保存済み取引の間引きで、空きポジションによる新候補・複利ロット・決済状態の変化を再現しないため、実行可能な現在のEAの比較とは区別する。

旧代理系列は完全なM5グリッドを要求し、部分セッションH1を落とす場合がある。実機はブローカーのnative H1を使用し、テスト開始前の過去履歴も利用し得る。旧診断との数値一致を前提にしない。実機の両アーム間では同じ系列定義を固定し、旧代理系列との差は後で個別に照合する。

## 固定条件と実行

新規EA `Wave33H1EfficiencyVerifier` v1.92を使用。v1.91および既存共有コードを変更しない。同じEX5・キャッシュ・銘柄仕様・入力54個を凍結し、取引判断の差は `InpSkipH1LowEfficiency` のfalse/trueだけ。run tagはログ衝突防止のため異なる。

- Bybit-Live / XAUUSD+ / M5×M1、チャートM1。
- 2025.01.01〜2025.02.01、ブローカー時刻。UTC換算は未検証。
- 全ティック・リアルティックを要求(Model=4)。202501.tkcの存在だけでは完全性を保証しない。実行後に補完・欠落・代替生成の有無をログで点検する。
- 初期資金5000 USD、レバレッジ100、既存1%リスク入力。これは研究用の継承条件であり、実運用の推奨リスクではない。
- +1Rで半分利確、その時点では元SL。+1.5RでSLを+1Rへ、その後0.5R刻み。固定最終TPなし。
- 初回約定から24時間、週末前5分、逆①後のコスト込みプラス決済を継承。
- 描画OFF・スクリーンショットOFFは両方同じ。既存の往復・文脈フィルタ入力等も同一。
- 分離portable runtimeを2個用意。専用ポート39410/39411。通常チャートのEA注文とDLLを無効化し、発注はEAのテスター専用ガード内。
- 2024/2025 HCCと202412/202501 TKC、銘柄仕様を同じサーバーから複製しSHA256一致を検査。実行後の実際のバー系列も検査する。
- prepare.ps1で凍結、launch.ps1 -Executeで2本を開始。バックテスト起動後は依頼どおりエージェント作業を停止し、ユーザーの再開連絡まで待つ。自動解析・自動再実行なし。

## 実行後に確認すること

1. 両方が対象期間の末尾まで完了したか。途中終了・初期化失敗・未決済は欠落と分ける。
2. 純粋計算45チェックのPASS、native CSVの列数、13終値の独立Decimal再計算、形成中/未来足ゼロ、境界・欠測・ギャップ処理。H1 native対旧proxyは通常時、再開時、週末、1/20の部分時間帯、開始時で比較する。
3. 実際に使用した履歴・ティック方式・実行コスト・サーバー・入力・銘柄仕様。両アームの同一時刻バー一致。異なれば戦略比較は保留。
4. native約定台帳とレポートの利益・損失・PF・取引数、部分利確/手数料/swap/最終決済、元のリスクを分母としたRを独立照合する。
5. OFFの全約定を分母に、ONの保持/除外/新規発生を対応付ける。H1のSKIPは週末・busy・ロット制約より前なので、SKIP件数をそのまま回避取引数と呼ばない。
6. 件数、総R、元候補あたりR、PF、DD、連敗、取引日、方向別・日別集中、除外した勝ち/負け、欠測許可を併記。取引数減少のみを改善としない。
7. 同月内の探索的比較であること、既知の2月悪化、V字・新トレンド抑制・ヒゲ未観測の限界を残す。1月改善だけでは採用しない。
