# 3波3波・初版の仮定とレビュー境界

日付: 2026-10-20。根拠: ユーザー提供「3波3波EA 実装・目視検証仕様書 v1.0」。動画画像、動画原本、元の検証データは未提供。本書は実装前の解釈・確認事項であり、検証結果や動画一致の証明ではない。

## 今回の目的と独立性

新規 `Wave33VisualVerifier` を XAUUSD のビジュアル検証用に作成する。M15×M5 と M5×M1、LONG/SHORT を独立に観測する。既存EA・既存研究の判定を変更しない。利益、PF、最適化、OOS・デモ・実運用への昇格は今回の合否基準ではない。

## ルールと仮定の境界

|領域|根拠のある方針|機械化で明示する仮定・確認点|
|---|---|---|
|上位足|逆トレンドの戻り高値／押し安値突破を第1波候補にする|左右2本の確定スイング、構造の組合せ、同値高安の扱いは初版の仮定。構造を認識できない足は強引に候補化しない|
|第1波|始点・終点を描画し、第2波を追跡する|突破後の確定スイングを終点に採用。高安が生じた時刻と、その高安が確定して利用可能になった時刻を分離する|
|Fib|38.2～61.8%を監視する|ヒゲ接触・終値接触、61.8%超過は設定と診断に分離。初期値で61.8%超過を即失格にしない|
|下位足|調整内部の逆構造否定を待つ|LH/LL または HH/HL の確定スイングで構造を定義。終値突破を初版トリガーにする|
|斜線|M1では確定した2点のトレンドライン突破も比較する|評価対象足より前に2点とも確定している必要がある。線の終値評価、実体が線を跨ぐこと、勢いは同じ条件ではない|
|波の呼称|上位足第3波の初動を狙う|逆構造否定の初動を、下位足1→2→3の厳密な波カウントと同一視しない。entry classification を残す|
|支持抵抗|既知の高安と H1 方向を判断材料にする|初期値 DISPLAY_ONLY。抵抗の近さや H1 逆行を暗黙の除外条件にしない|
|SL/TP|第2波極値の外側、初期RR1.0|spread、tick size、stop level、追加幅、ロット計算、抵抗CAP後RRを記録する。発注失敗も候補の一部|

初版の時間境界として、第2波内部の下位足の探索は「第1波終点を含む上位足の終了時刻」以降とする。終点足の中で、高値／安値が生じた後の下位足を厳密に同定する処理は行わない。このため終点足内部の早い調整を拾わない可能性があり、動画との認識差として比較する。確定待ちの間に既に閉じた調整足は、終点が認識可能になった現在時刻で状態を特徴づけるためにのみ利用し、過去のシグナルを発行しない。

下位足は直近2高値・2安値が交互に並び、LONGの逆調整はLH/LL、SHORTの逆調整はHH/HLとなることを確認する。高値側で終わる交互配列と安値側で終わる交互配列の両方を扱う。選択したトリガーのシグナル発生までは新たに確定したスイングで線を更新し、選択しなかったトリガーの診断観測だけを理由に発注側の線を固定しない。各トリガーの最初の観測時刻・価格と、その時点のアンカーはイベント行で追跡する。

## 因果性のレビュー項目

1. 現在足を確定足として使わない。スイングの右側確認本数を消費した足が閉じ、EAが最初に観測できたティックの時刻を `known_at` にする。名目の足終了時刻と実際の観測時刻は一致しない場合がある。
2. スイング位置にマーカーを置く場合も、認識時刻を併記する。水平・斜線は認識時刻より左へ延長しない。
3. 評価対象の下位足が始まる前から既知だった判定線だけを突破判定に使う。同じ終端時刻で上位足と下位足が確定する場合の処理順でこの制約を破らない。
4. 新しい第1波終点の確定後、過去の下位足へ遡って新規の実行可能シグナルを発行しない。履歴から第2波の既存状態を復元する場合は、その観測・認識時刻を分ける。
5. W1・W2 の極値更新で古いマーカーやログを消さない。表示再生成で状態・注文が変わらない。
6. 一度使ったセットアップを再利用しない。`setup_id` に銘柄・時間足・方向・候補足時刻・連番を含め、実行をまたぐ完全な識別には `resolved_run_tag` と `setup_id` の組を使う。
7. PIVOT と TRENDLINE の双方の到達を観測しても、注文は同一セットアップ1回。後着トリガーを観測できない終了設計なら、その欠落を制約として明記する。
8. テスター終了時の未成立候補も残し、成立例だけを抽出しない。TIMEOUT等は排除、FIB_TOO_DEEP等の初期値は計測として区別する。

## 注文と描画のレビュー項目

- 初期値は診断のみ、注文は MT5 テスター内だけ。通常チャートのデモ・実口座では発注しない。
- 1%をSLまでの金額リスクとして算出。lot step に切り下げ、min lot未満をmin lotへ強制増量しない。CFD等も銘柄契約に応じた損益計算を使う。
- LONG/SHORT の Bid/Ask と停止水準を区別する。tick size にSL/TPを外側へ正規化し、抵抗CAP後のTPが利益側にあることと実効RRを確認する。
- シグナル時刻、order sent、fill 時刻・価格を分離。注文失敗のretcode・理由、ポジション制約による見送りも描画する。
- 緑ENTRY、赤SL、緑TPは注文OFFでも描画する。候補・未成立・損失例・失効のオブジェクトも保持する。
- v1.20のユーザー指摘で、保持した水平線を未来まで右延長し続ける表示を廃止。判定線/Fibはシグナルまたは候補終了で止め、発注したSL/TPは決済またはテスト終了で止める。診断SL/TP・抵抗は短線。履歴は削除せず当時の区間に残す。線の延長状態は描画モジュール内だけで管理し、エンジンの状態・発注を変更しない。注文ONの専用プリセットは診断用とは別に保存する。
- 固定パネルの詳細情報は保持する。2026-10-20のユーザー指摘により、v1.10では大きな左上パネルを廃止し、初期表示はOFFとする。任意の小さい左下凡例のtooltipで詳細を読める。常時表示は①第1波・②押し戻り・ENTRY・SL/TP・見送りを中心にする。確定した山谷を実際の足位置で破線で結ぶが、生成はknown_at以後のみ。判定線の開始は引き続きknown_atとする。これは表示の変更で、スイング・候補・発注条件は変更しない。
- CSVは全イベントを発生順に保持し、同じシグナルの過去行を約定後情報で上書きしない。後のfill/exitイベントはsetup IDで結合する。

## 検証と未確定事項

必要な確認は、0 errors / 0 warnings、左右2本の確定遅延、LONG/SHORTの鏡像分岐、各状態への到達、同時刻の上位足・下位足処理、注文OFF/テスターON/通常チャート禁止、失効描画とCSV、両時間足各5事例の一覧である。該当事例が不足すれば件数をそのまま報告する。

合成バーのユニット試験は境界条件の証拠になるが、実際のMT5実行、ビジュアル描画、動画との一致を代替しない。画像未提供のため、今回一覧化した事例の「動画と一致」判定はユーザーによる目視レビュー待ちとする。ユーザーが差を指摘した場合は、差と知り得た時刻を説明してから仕様・ロジックを修正し、成績改善の目的で条件を増減しない。

実行証拠・サンプル一覧・制約の確定版は、今回のdevlogと `reports/qa/` の実ファイルへ接続する。

## 参照API

金額リスクの評価は、口座通貨で結果を返す [OrderCalcProfit](https://www.mql5.com/en/docs/trading/ordercalcprofit) を確認する。銘柄ごとの価格刻み・lot刻み・min/max lot・stop/freeze level は [MQL5 Symbol Properties](https://www.mql5.com/en/docs/constants/environment_state/marketinfoconstants) が一次資料。これらのAPIを使ったこと自体を、ブローカー注文受付の保証とは扱わず、実注文のretcodeも残す。

[ObjectCreate](https://www.mql5.com/en/book/applications/objects/objects_create) のオブジェクト名と [ChartScreenShot](https://www.mql5.com/en/docs/chart_operations/chartscreenshot) のファイル名には63文字の上限がある。run tag・フルsetup ID・イベント名を単純連結して上限を越えないよう、短い識別子とフルIDの対応をログ・tooltipで残す。画像保存APIが成功した場合も、保存ファイルを実際に開き、描画を確認する。
