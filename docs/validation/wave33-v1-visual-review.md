# 3波3波 v1.80 — MT5目視照合手順

v1.80は、元の確定①終点を起点とする逆①候補が出た時点で、古い未発注候補を終了する。青①が反対方向に見えるだけでは除外せず、同じ終点の日時・価格を共有することが必要。注文送信中・約定済みは保護し、既存の逆①確定後のプラス決済を併用する。原因ID・共有終点・判断時刻を見送りのtooltipとCSVで確認する。

RR基本TPが①極値より手前なら、LONGは①高値より少し下、SHORTは①安値より少し上まで延長する。元から遠いTPは維持する。「TP①手前」のtooltipに基本TP・最終TP・実RR・根拠の①終点が表示される。SLは維持し、保有後の未来の①はTP計算へ入れない。`InpCancelConnectedOpposite`と`InpExtendTPToWave1`を個別にOFFへ戻せる。余裕は`InpTPWave1BufferPoints`（初期10ポイント）・現在スプレッド・1ティックの最大値。

[v1.80 A設定](../../reports/presets/wave33-v180-A-M15-M5-orders.set) / [B設定](../../reports/presets/wave33-v180-B-M5-M1-orders.set)、[実行手順](wave33-tester-orders.md)、[固定短期QA・描画・旧版回帰](../../reports/qa/w33v180/README.md)。下記のv1.71以前の説明と件数は変更履歴であり、最新実装の成績ではない。

新設定は [A M15/M5](../../reports/presets/wave33-v170-A-M15-M5-orders.set) / [B M5/M1](../../reports/presets/wave33-v170-B-M5-M1-orders.set)。固定区間はXAUUSD+、2020.10.01〜2020.11.18、5,000 USD。`InpExtendWave1BeforeFib=true`が既定値で、falseでこの変更だけをOFFにできる。RR入力、61.8%上位終値除外、逆①確定後のプラス決済は維持した。[v1.70検証・10事例・制約](../../reports/qa/w33ext/README.md) / [画像2件の終点比較](../../reports/qa/w33ext/user_image_review.md)。以下の過去版の説明・件数は履歴として残す。現在の実行手順は[注文手順](wave33-tester-orders.md)。

v1.60では、実保有後の逆方向の青①確定を黄色の待機表示で記録する。推定コスト込み損益が最初にプラスになったティックで決済を要求し、黄色のEXITを実約定時刻・価格に残す。元の反対波の位置と「それをEAが知った時刻」を混同しない。反対①の認識後もSL/TPを維持し、プラスへ戻らずSLとなる事例もレビューする。根拠となる候補ID、純損益推定、実際の決済理由とRはCSVに保存する。[実行手順](wave33-tester-orders.md)を参照。下記のv1.50以前の件数は過去版の証拠。

## MT5で開く

1. `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/compile.ps1 -Source mql/Experts/Wave33VisualVerifier.mq5 -LogPath reports/compile/wave33-v1.log` でビルドする。
2. MT5ストラテジーテスターで `dev\mql\Experts\Wave33VisualVerifier.ex5` を選ぶ。配置先によって表示パスは変わる。
3. v1.70の固定比較はXAUUSD+を選択。「全ティック（リアルティックに基づく）」、「ビジュアルモード」を選択する。期間は2020.10.01〜2020.11.18。短期開始ではスイングの蓄積が変わる。証拠金5,000 USD、レバレッジ1:100。時刻はテスターのブローカー時刻で、UTC換算は推測しない。今回の保存区間は実ティックがなく生成ティックへ代替された。
4. パターンAはチャートM5、[v1.70 Aプリセット](../../reports/presets/wave33-v170-A-M15-M5-orders.set)を読み込む。パターンBはチャートM1、[v1.70 Bプリセット](../../reports/presets/wave33-v170-B-M5-M1-orders.set)を読み込む。別々に実行する。専用ビジュアルINIは [A](../../reports/backtest/wave33-v170-A-M15-M5-orders-visual.ini)・[B](../../reports/backtest/wave33-v170-B-M5-M1-orders-visual.ini)。
5. 上記SETは注文ON。診断だけなら読み込み後に `InpEnableTesterOrders=false` へ変更する。注文OFFでも、リスク確認を通過した候補のENTRY・SL・TPを描画し、余地不足等で除外した候補はENTRYにせず見送り理由を残す。通常チャートは入力値にかかわらず注文しない。最適化モードは起動を拒否する。[注文ONの詳しい手順](wave33-tester-orders.md)。
6. Bの比較は `InpTriggerMode=0`（PIVOT）、`1`（TRENDLINE）、`2`（先着）を別テストにする。同足で両方成立した先着モードはPIVOTを採用する。採用前は新しい確定スイングに追随し、採用後はその時点の固定ラインで後着トリガーを観測する。先着した未採用トリガーと採用トリガーのアンカーが異なる場合は、各イベント行で区別する。失効・タイムアウト・実ポジション決済で観測を終える。

v1.50のSETは **`InpRejectDeepFibClose=true`、`InpRejectDeepFib=false`**、`InpStrictWaveLifecycle=true`、`InpLowerRecognition=2`（`NORMALIZED_OR_SIMPLE`）、`InpMinWave1RoomR=0.25`、`InpRewardR=1.0`。v1.40 SETには新しい終値除外入力がないため、上記のv1.50 SETを使う。終値除外のOFF/ON比較では `InpRejectDeepFibClose` だけを変更する。単純反応はPIVOTによる新しい終値突破の観測であり、TRENDLINEだけを選ぶ比較ではその反応からシグナルを出さない。

v1.50同梱INIはXAUUSD+・5,000 USDを使い、Aが2018.02.01〜2019.01.17、Bが2019.01.02〜2019.01.17の固定比較と同じ初期値を持つ。Aを短区間で開始すると蓄積スイングが変わるため、同じ画像の再現には固定開始日を使う。[INIの使い方](wave33-tester-orders.md#iniは起動設定の補助として使う)を参照。

## 表示の読み方

2026-10-20の表示改訂（EA v1.10）は、ユーザーの「左上の文字で波が隠れる」「色だけでは分からない」という指摘と、指定された `MultiTF_3WaveIn3Wave_Visualizer_v1.05_InvalidationReset.mq5` の描き方を反映した。参照インジケーターと売買ロジックは変更しない。

まず **青い太線の「① 第1波」→ オレンジの「② 押し・戻り」→ 緑の「ENTRY 買い／売り」** の順に読む。青系の細い破線が上位足、紫の細い破線が下位足の確定した山谷を結ぶ。紫の水平線または斜線が転換判定の線、赤紫の「抵抗／支持」が採用された近隣水準。赤がSL、緑がTP。「見送り」には短い理由を添える。

初期値は `InpShowInfoPanel=false`、`InpDiagnosticLabels=false`、`InpShowSwingPaths=true`。大きな左上パネルは表示しない。`InpShowInfoPanel=true` では左下に小さい凡例を表示し、状態・各時刻などの長い情報はそのtooltipで読む。細かい高安ラベルや診断文字が必要な場合だけ `InpDiagnosticLabels=true` にする。W1の暫定線は細い点線、確定線は太線。W2更新点と過去の候補は残す。

Fib帯はローソク足を隠さないオレンジの枠表示。旧下位ラインは新しいラインが既知となった時刻で右延長を止め、その履歴を残す。ラベルを短くし、元スイング時刻などの詳細はtooltipとCSVへ分ける。水平線・斜線の2点は表示足1本以上の間隔を取り、M5で同じ足内に潰れる表示不具合を防ぐ。

v1.20では、水平線・転換斜線を**無限の右延長がない有限線**へ変更した。候補が続く間は既知のイベント時刻まで延ばし、シグナル・失効・見送りで判定線とFib帯を止める。診断だけのSL/TP・抵抗は短い線。実発注したSL/TP・抵抗はポジション決済またはテスト終了で止め、過去の足の区間に履歴を残す。部分決済では止めない。最初の表示と同時刻終了の線は、見えるように表示足1本分の短いマーカーとする。手動水平線も取付時刻から下位足12本分の有限表示で、自動判定には使わない。

v1.30では、所属する第2波の最深値を更新した下位構造だけを使う。調整後、未成立のまま下位確定終値が固定W1終点を越えた場合は、灰色の点と「初動を逃したため終了」を表示する。その候補は後の小さな転換で復活しない。灰色点はEAが知った時刻、元の足・確定時刻はtooltipとCSVで確認する。この境界は動画と比較するための仮定であり、厳密な下位1→2→3の認定ではない。

v1.40では、紫の抵抗／支持候補を `R`＋短いハッシュで元の点と対応付ける。ラベルとtooltipに時間足・高値/安値・元日時・known（確定して知った時刻）・adopted（今回採用した時刻）を分ける。過去の高安を今回の候補に採用したことと、当時すでにそのシナリオを知っていたことを混同しない。方向に対して抵抗・支持と断定しにくい反対側の高安は「参考」と表示する。

青①終点は紫の候補と別の出所として示し、「①高値まで／①安値まで xR」で余地を表示する。`wave1_room_r` は発注可能なAsk/Bidから固定W1終点までの符号付き距離÷丸め後SL幅。初期値の0.25R未満は `WAVE1_ROOM_TOO_SMALL` で見送り、ENTRYは描かない。SL/TP・余地と見送りの根拠は追跡可能なまま残す。最低0.25Rは動画の確定ルールではない比較仮定で、`InpMinWave1RoomR=0` により無効化できる。正の余地が利益やW1突破を保証するものではない。

下位認識は `lower_recognition` で区別する。`InpLowerRecognition=0` は `STRICT_COUNTERTREND`、`1` は確定した同側スイングを整理する `NORMALIZED_COUNTERTREND`、初期値 `2` はこれに `SIMPLE_REACTION_BREAK` を加える。単純反応は、同じ第2波の確定極値→最初の反対側pivot→新しい終値突破を追う別の認識であり、厳密な下位1→2→3の成立を主張しない。元のpivotと既知時刻をイベントに残し、形成途中の足や後から知ったpivotで過去のENTRYを作らない。

v1.50の終値除外は、Aでは**M15**、Bでは**M5**の確定終値で判断する。固定したW1に対する押し率が61.8%を厳密に超えたときだけ `FIB_CLOSE_TOO_DEEP` で候補を終了する。61.8%ちょうどは許容し、ヒゲだけの超過はこの条件では失格にしない。画面には「見送り: M15終値の押し xx.x%」またはM5のcaptionを、EAが判断できた時刻に表示する。元足と判断時刻はtooltip・CSVで分けて確認する。

W1終点の確定待ち中に既に上位終値違反があった場合は、W1確定時にその履歴を初めて評価する。終点足そのものをW2へ含めず、その次の上位足以降を対象にする。履歴を過去時刻の失効や注文として描き直さない。同じ確定時刻の上位足・下位足は上位足から処理し、終値除外された候補から同時刻の下位シグナルを出さない。TIMEOUT・起点破壊の既存優先を維持し、成立済みシグナルや保有中ポジションへこの除外を遡及適用しない。

山谷の点とそれを結ぶ破線は、**スイングを知った後に初めて**実際の高安の足位置へ描く。上位足の極値は、その上位足の中の既に閉じた下位足で位置を合わせる。高安の元時刻、描画位置、認識時刻はtooltipに分けて記録する。同じ足で高値と安値が両方確定する場合は、OHLCから先後を決められないためその足の2点を結ばない。一般の連結は連続する逆側pivot間のみで、同じ側が続くときは最新の点を次の起点にする。

W1・W2の脚も実際の高安位置を結ぶ。これらの波形の線は、当時その線を既に知っていたことを意味しない。Fib帯、水平の判定線、転換用トレンドラインの左端は利用可能になった時刻から始まる。PIVOTでは水平線、TRENDLINEでは斜線、先着モードでは両方の判定線を表示する。

`InpKeepObjects=true` ならEA終了処理ではオブジェクトを削除しない。テスター画面自体の閉鎖・再作成による消去はMT5の動作に依存するため、必要な場面はPNGも残す。

`InpScreenshots=true` はビジュアルモードでのみ `ChartScreenShot` を要求する。`DRAWING_CAPTURE` 行にファイル名を保存。画像はテスターエージェントの `MQL5\Files`、CSVは「データフォルダを開く」の同階層 `Terminal\Common\Files`。`InpScreenshotLimit` は保存枚数の上限であり、候補計算・CSV・チャート保持の件数を制限しない。画像名・オブジェクト名には短いハッシュを用い、CSVの完全なsetup IDと紐付ける。

今回のbuild 6230では、実際にVisual=1で最後まで実行しても `ChartScreenShot=true` のPNGが生成されなかった。したがって `DRAWING_CAPTURE` は保存要求の記録であり、画像ファイルの実在・内容確認なしに描画合格と扱わない。成績グラフPNGもEA描画の証拠には数えない。

補助確認として [記録描画ランナー](../../scripts/render-wave33-recorded-review.ps1) と [描画専用EA](../../mql/Experts/tests/Wave33DrawingReplay.mq5) を用意した。実CSVの事例を同じDisplayモジュールへ渡し、実データのM1バーを各判断時刻で切った専用カスタム銘柄に表示する。初版ではXAUUSDの各5事例を確認した。売買・シグナルの再計算を行わない。これは**通常チャート上の記録イベント再生画像**であり、テスター画面の直接キャプチャではない。元CSVに含まれないW1暫定極値の全履歴などは復元しない。実テスター画面の操作・動画との照合はユーザーの目視レビューに残る。

## 初版から維持する仮定とv1.50までの変更

- 左右2本の厳密な高安比較。同値高安は一意なスイングにしない。右側2本が閉じてから利用する。
- 逆構造は2高値と2安値のLH/LL（ショートはHH/HL）を使い、高安が交互に並ぶ2つの位相を認める。v1.40の初期値は確定スイングを整理した認識と単純反応を区別して扱う。これらは動画画像と照合すべき機械化仮定。
- W1終点はブレイク足以後の暫定極値がスイング確定したもの。極値を固定した後、過去の下位足の押しを現在時刻で記録することはあるが、過去へシグナルを発行しない。
- Fib到達は確定下位足の高安レンジと38.2〜61.8%帯が重なった履歴を監視し、ヒゲでも到達とする。到達履歴とエントリー時点の価格が帯内にあることは別条件。最深高安の61.8%超は `InpRejectDeepFib=false` のまま計測だけを続け、v1.50は別入力 `InpRejectDeepFibClose=true` により上位確定終値の61.8%超を除外する。`InpRequireFibTouch=false` は今回の比較では使わない。
- 下位ラインは評価足が始まる時点で既知であること。終値が前の終値からラインを跨いだ最初の足で転換を認定。ライン突破後の押し待ちは加えない。
- トレンドラインは確定2点を結び、足の終端時刻で価格を評価。実体比率・14本のATRに対する実体幅は記録のみ。大きな足による除外はしない。
- 一方向につきアクティブな1セットアップ。継続中に別の上位ブレイクが出た場合は候補と `ACTIVE_SETUP_SAME_DIRECTION` を記録する。無制限の同時セットアップ管理は初版に含めない。
- タイムアウトは上位足96本。origin破壊は除外。成立後は同一セットアップから再発注しない。未完了は停止時に `CENSORED_AT_STOP` を残す。
- 近隣抵抗は確定M5/M15/H1スイングと当該W1終点。H1はWITH/AGAINST/RANGEを記録し、除外しない。
- 手動価格はセミコロン区切り `InpManualLevels`。取付時刻以後の表示のみ。自動シグナル・SL・TP・抵抗検索へ混入しない。
- 発注時のSL余裕はspread + max(stops,freeze) + 追加10points。SL/TPはtick sizeに正規化。1%はSLまでの口座通貨損失予算。lot stepで切り下げ、min lot未満は見送る。手数料・スリッページによる最終損失は予算と一致する保証はない。
- 抵抗モード初期値はDISPLAY_ONLY。SKIPは必要RR未満で除外、CAPは抵抗の手前へTPを縮め、`actual_rr` を再計算。目標 `intended_rr` と分離する。
- 起動前の候補は再生しない。開始後にスイングを蓄積するため、区間冒頭にはウォームアップによる未検出部分がある。

## CSVと目視レビュー

`<resolved_run_tag>_events.csv` は発生順の追記イベント。`<resolved_run_tag>_config.csv` は入力と銘柄仕様。`<resolved_run_tag>_upper_bars.csv` はEAが受理した上位足の全OHLCで、`symbol`、`tf`、`bar_time`、`closed_at`、`known_at`、`open`、`high`、`low`、`close` を保存する。AはM15、BはM5で、違反足だけの抜粋ではない。いずれも `Terminal\Common\Files` に保存する。既存タグが存在すれば時刻サフィックスを付け、過去結果を上書きしない。候補の最終状態だけで過去行を上書きしない。

`*_time` / `signal_at` は対象足・名目の成立時刻、`*_known_at` / `event_at` はEAが観測した時刻。`order_sent_at` と `fill_at` は発注と実約定。完成逆構造の `lower_pivot_times` は高値旧/新、安値旧/新のUnix秒を `|` で列挙し、単純反応ではW2極値・最初の反対側pivotの2点を列挙する。テスター停止時の評価は未完了として扱う。

上位終値の最初の違反には、次の5フィールドを保存する。

| フィールド | 意味 |
|---|---|
| `fib_close_bar_time` | 違反した上位ローソク足の開始時刻 |
| `fib_close_at` | その足の終値が確定する時刻 |
| `fib_close_known_at` | 固定W1を使って違反を判断できた時刻 |
| `fib_close_price` | 判定に使った上位終値 |
| `fib_close_ratio` | その終値のW1に対する押し率（0.618＝61.8%） |

除外ONでは `FIB_CLOSE_TOO_DEEP` を除外イベントと失効理由に残す。比較のOFFでは同じ最初の違反を `MEASUREMENT` として記録し、終値違反だけでは候補を終了しない。ヒゲの最深値を記録する `retracement_ratio` / `FIB_TOO_DEEP` と取り違えず、`upper_bars.csv` の該当足と照合する。

約定ポジションの決済Rは、profit + commission + swap + fee を初期SL損失金額で割る。診断シグナルの仮想勝敗は計算しない。診断行の `realized_r=0` は取引なしであり、損益ゼロの取引ではない。

成立例に `DIAGNOSTIC_ONLY` と `WAVE1_ORIGIN_BROKEN` / `TIMEOUT` が同居する場合は、成立後の後着トリガー監視が終了した理由である。過去のENTRYを遡って不成立にした意味ではない。`reason_kind` と各イベントの時刻を合わせて読む。

両パターンの候補を最低5件ずつ、LONG/SHORTと成立/失効を含めて確認する。足りなければ観測数をそのまま記す。レビュー欄は「一致」「EAの認識遅れ／過剰判定」「動画から判断不能」の3区分。画像や説明が足りない箇所は3番目へ入れ、想像でルールを追加しない。

1. 上位の破った高安値と既知時刻、W1の始点・終点・認定遅延を確認。
2. Fib到達、最深押しとその観測時刻、下位LH/LLまたはHH/HLを確認。終値除外は上位終値・固定61.8%境界・`fib_close_*` の3時刻を別に照合する。
3. 判定線がその足の前に既知だったか、トリガー足と約定の時刻差を確認。
4. SLの根拠、目標/実効RR、抵抗距離、見送り理由を確認。
5. 勝敗とは独立に不一致箇所と差（本数・points）を書き、修正前に説明する。
