# M5初動を過ぎたM1候補の停止

ユーザーが「M5 Wave1高値突破後にM1 CHoCH/HLを待つ候補は遅い」と指摘。従来の終了判定が `found_choch && !found_hl` に限定されていたため、CHoCH前とHL確定後に穴があった。

共通エンジンで、最初のM5高値の確定終値突破までにM1 READYが完成しなければ終了する。同じ足で両方が成立するケースは採用。M1の無効化・再探索経路でも突破を忘れない。追加指標・フィルター・ピボット感度の調整は行わない。

同時にShared v1.07の高安をTF別の矢印・線幅で区別し、候補表示と実約定表示を分離。データ取得待ちで描画を消さず再試行し、インスタンス固有プレフィックスを採用した。

構造テスト26件・注文テスト19件合格、コンパイル0/0、31,580判定でEA/インジケーター一致。4月候補は19→14、PFは0.687→0.473。定義修正に成功したが、収益改善・件数増加の証拠にはならない。候補14件はすべて発注されており、件数課題は注文制御よりも「M1下降→CHoCH→高値→HL」の構造認識にある。次に調べる場合は、目視で期待する押しと2組のLH/LL必須定義との差を事例で照合する。ここを無断で緩めることはしない。

運用メインラインを変更せず、承認済み独立テスター内のみでEA実行。Market製品の538は本EAと無関係の別インジケーター読み込み失敗であり、認証設定・Market本体は変更しない。
