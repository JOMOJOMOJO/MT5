# Wave33 v1.85: 二段階利確と建値SL

ユーザーの指示は、従来の①手前への一括TP延長を、基本RR目標と①手前の目標で半分ずつ利確する処理へ変更し、最初の実利確後に残量のSLを建値へ移すこと。同時に一年分のバックテストを依頼された。[固定仕様](../../knowledge/experiments/2026-10-26-wave33-scaleout-plan.md)を先に保存し、エントリー条件と期間を固定した。

診断EAをv1.85へ更新し、`InpScaleOut=true` を追加した。近い目標で初期実約定数量の半分、遠い目標で残量を決済する。①の目標はエントリー時点の既知の固定極値を使う。OFFでは従来のTP延長を維持する。注文送信と実約定を分け、ユニークなdealの数量を累積し、半分の確認が済んでから実建値へSL変更を送る。

数量刻みにより半分は切り捨て。どちらかの数量が最低ロット未満なら、リスクを増やさず近い目標で全量決済する。建値の平均約定値が刻み外なら有利側へ1ティック以内の丸めを記録する。ストップ/フリーズ制約で変更できない間は元SLを維持する。建値は手数料等を除く価格上の建値であり、残量の純損益ゼロを保証しない。

逆①のプラス決済と部分利確の注文保留を共有して二重決済を防ぎ、元のSLリスクをRの分母として保存する。raw deal CSVにprofit、commission、swap、feeを残し、分割利確を独立した勝ち取引として数えない。元EA・Engine・Types・Ledger・往復/上位高安帯などの既存計算は作業前hashと照合して保持した。

機能検証では、受理直後にまだ観測できない建値SL変更が保留ガードで止まる経路が見つかった。5秒後に再確認し、価格が逆行して変更できないときも保留を解除して旧SLを保つよう修正した。独立CSV監査では理由中のセミコロンによる列ずれを検出し、文字列の引用と内部引用符エスケープを追加した。いずれも最終凍結ソースで再検証した。

最初の短期smokeは4条件638検査がPASSし、Bの分割ONでは実市場データの4ポジションで半分利確と建値変更まで到達した。年間開始前の表示レビューで、既存のラベル配置が古い時刻を保持して「旧時刻＋建値SL価格」の引出線を描く経路を発見した。建値SLと分割不可TPの表示に限り、変更線の始点時刻へアンカーを更新する。分割不可になった金色TP1の文字も全量決済へ変更する。通常のSL/TPの元アンカーは維持し、表示修正を売買条件の変更と混同しない。

[QA](../../reports/qa/w33_scaleout_20261026/README.md)は6ケース2,904項目、別CSV監査102項目が失敗0。両方向・両時間足・二つの目標順序・最小ロット・OFFを実テスター注文で確認し、拒否・重複通知・未反映SLの待機解除も確認した。実口座方式はRETAIL_HEDGINGのみ。main/ハーネスは各0 errors / 0 warnings。[最終22検査](../../reports/qa/w33_scaleout_20261026/final_verification.json)と表示26項目の確認・hash固定後に年間試験を許可した。

年間は[固定4条件](../../reports/backtest/runs/wave33_v185_2020/PLAN.md)、XAUUSD+・2020年、初期5,000 USD、risk 1%、RR 1.0、A=M15/M5とB=M5/M1のOFF/ON。既存端末を止めず、専用portable runnerを使う。標準backtestスクリプトが既存端末共通設定も変更するため隔離runnerに限定した。2026年は使わず、OOS・実運用昇格と扱わない。生成ティックとリアルティックを明示的に区別する。[結果と原本](../../reports/backtest/runs/wave33_v185_2020/README.md)を参照。

既存の逆①・Fib除外・接続両側見送り・往復/上位足フィルターを同時に調整せず、一つの出口変更として比較する。出口により保有時間と次の候補の採否、複利ロットも変わり得るため、OFF/ONの損益差を同一の約定集合に対する純粋なTP差とは解釈しない。

ユーザー用は [A分割ON](../../presets/wave33/Wave33ScaleOut_v185_A_On.set) / [B分割ON](../../presets/wave33/Wave33ScaleOut_v185_B_On.set)。全45入力を明示し、注文と描画をON、通常チャート注文は引き続き禁止する。

途中のA年間原本から、nativeの125取引が元positionでは82エントリーであることを別集計で確認した。[集計上の再利用ルール](../../knowledge/patterns/2026-10-26-partial-exits-and-trade-counts.md)と[未公開の記事種](../../content/seeds/2026-10-26-partial-exits-and-trade-counts.md)へ保存し、勝率・連敗改善を正の期待値と混同しないよう根拠を残した。
