# Wave33: 1Rで半分利確、その後0.5R刻みのSL

ユーザー指定で[出口ルール](../../knowledge/experiments/2026-10-26-wave33-half-and-step-plan.md)を新規 `Wave33DayTradePartialVerifier` v1.91に実装。旧v1.90のEA・header・プリセットと、既存の原版・診断EAは保持する。未コミットの他作業も保持し、pushしない。

旧部分利確の「直後に建値」「①手前の最終TP」「数量不足なら全量利確」は今回の仕様と異なるため呼び出さず、専用の純粋helperとnative adapterに分離した。リスク予算を増やさず二等分可能な数量へ切り下げ、半分の約定確認前にはSLを移さない。1.5R到達で残りSLを1R、以降0.5R刻み。1Rは初回の約定と初期SL、純損益Rは初回全量の金額リスクで固定する。

24時間、週末前、逆①後の取引全体プラス決済を保持。入口ルールは変更せず、結果を見て閾値を調整しない。小ロットの二等分不能・部分約定の残数・各pending注文の競合・SL実確認をログで追跡できる。[ビルド／QA／プリセット／確認方法](../../reports/qa/w33_daypartial_20261026/README.md)。実行開始後はユーザーから再開の指示が来るまで停止する。

独立レビューで、絶対誤差1e-8を数量比較に使うと最小step1e-8の銘柄で未決済を半分済みと誤認するケースを検出。新規forkの数量判定を銘柄stepに合わせ、純粋境界テストも追加する。既存EAの挙動には混入しない。

前回v1.90 native QAの226件FAILも照合した。全件が市場閉場の最初の1分に出たもので、元記録はFAILのまま保存。新harnessでは明示的な市場開始待ちとwatchdogに分ける。native再試験の結果はまだ未確認。実装・QAの段階なので新規公開seedは作成しない。

EA・純粋script・native harnessのコンパイルは全件0 errors / 0 warnings。静的確認63件PASS、既存23ファイルは作業前SHA256から変更なし。判定テストの実行結果とnative約定確認は、起動後ユーザーからの再開を待つ。
