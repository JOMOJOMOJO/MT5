# Step 15A statistical detector executable specification

## Scope

The 24 `TS15A-*` tests are fixed before production V1 implementation. Inputs
are under `tests/tick_shock/fixtures/`; literal expected values are under
`tests/tick_shock/expected/`. They were generated by the independent
`tools/tick_shock/step15a_independent_oracle.py`, which imports no production
module. The MQL test support reads those files and calls the production API;
it does not calculate an alternative expected value.

## Case map

| Area | Test IDs | Required observation |
|---|---|---|
| returns and Mid | `TS15A-RET-001`, `TS15A-MID-001` | exact natural-log Mid returns |
| tick chronology | `TS15A-SAMEMSC-001`, `TS15A-IRREG-001`, `TS15A-STALE-001`, `TS15A-FUTURE-001` | last same-ms quote, exact past anchors, 500ms age, no future read |
| separation/noise | `TS15A-SPREAD-001`, `TS15A-ANOMALY-001`, `TS15A-NOISE-001` | liquidity/cost separate; robust estimator observably attenuates |
| persistence | `TS15A-REVERSAL-001`, `TS15A-PERSIST-001`, `TS15A-CLOCK-001`, `TS15A-BACKDATE-001` | next-boundary confirmation and no backdating |
| local scale | `TS15A-VOL-HIGH-001`, `TS15A-VOL-LOW-001` | frozen bipower formula and local-score response |
| conditioning | `TS15A-TOD-001`, `TS15A-EXCLUDE-001`, `TS15A-CALIB-001` | bucket boundaries, 2s exclusion, 10,000 minimum |
| tail/multiplicity | `TS15A-QUANTILE-001`, `TS15A-SEVERITY-001`, `TS15A-MULTI-001` | plus-one rank, inclusive bands, Holm adjustment |
| identity | `TS15A-CLUSTER-001`, `TS15A-STRICT-001`, `TS15A-PROV-001` | horizon dedup, exact V0, versioned provenance |

## Status rules

- Before implementation, a missing production API is an expected RED/XFAIL,
  not SKIP.
- `STRICT_V0` is PASS only with existing Step 14R production evidence.
- After implementation, every deterministic V1 row must be observed as MATCH
  by the compiled MQL detector harness. No XFAIL, XPASS, BLOCKED, or unexpected
  SKIP is allowed.
- Fixture/expected hashes are frozen at the RED commit. A later hash change is
  a test-integrity failure and cannot be justified by implementation output.
