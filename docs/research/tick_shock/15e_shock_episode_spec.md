# Step 15E shock episode and outcome specification

## Production contract

The production-callable research module consumes grouped real quotes and
already-confirmed `TAIL_V1_PERSISTENT` events. It owns one bounded episode
context per symbol. It records compact episode and checkpoint rows and never
sends, checks or modifies orders. The EA and deterministic harness call the
same functions.

An eligible event received in `IDLE` allocates the episode and freezes event,
cluster, direction, anchor quote, detector severity, Step 15D labels, causal
pre-M1 scale and data provenance. An eligible event during ACTIVE or COOLDOWN
is a repeat only. ACTIVE lasts exactly 900,000 ms. The first real quote at or
after each target records the checkpoint. At end-of-run, incomplete ACTIVE
episodes are purged rather than completed with a stale quote.

## Required output contracts

`medium_horizon_episode_summary.csv` is one row per episode. It includes
identity, anchor clocks/prices, repeat features, duration/status, pre-M1 scale,
quality flags, MFE/MAE and their clocks, recross, extrema, activity/spread and
integrity counters.

`medium_horizon_response.csv` is one row per episode/checkpoint. It includes
target/quote/processing clocks, quote availability, Mid/Bid/Ask, signed and
absolute log returns, shock-direction return, executable Long/Short return,
MFE/MAE, point/pip/spread/shock/pre-volatility scales and provenance.

`medium_horizon_entry_comparison.csv` is one row per episode/entry clock/exit
clock/direction/cost view. Entry clocks are confirmation, +30s, +60s, +120s
and causal transition. The first real quote strictly after the signal and at
or after eligibility fills the entry. Fixed exits use the first real quote at
or after their target. It records gross-mid, spread-only, known-cost,
1.25x-spread sensitivity, break-even additional cost and formal-net status.

## Deterministic validation contract

The frozen `TS15E-*` fixtures and expected CSV files are independent oracles.
They cover episode allocation/repeats/cooldown/end purge, checkpoint clocks,
same-millisecond grouping, stale/missing/fallback handling, completed-M1
volatility, Bid/Ask P&L, MFE/MAE/recross, delayed causal entries, leakage,
multicurrency ordering, first-touch ties, cursor/capacity/provenance, Step 15D
identity and zero orders. Expected values are not generated by production
functions.

RED is the absence of the Step 15E production module/API. GREEN requires the
compiled MQL harness to call the same module instantiated by the research EA,
plus a separate Python oracle that only reads frozen fixture/expected files.

## Non-goals

This specification does not change the detector, Step 15D path labels,
strategies, thresholds, stops, RR, delay/spread grids, 120-second strategy
behavior or order availability. It does not confer OOS, selection-validation,
formal-net or production status.
