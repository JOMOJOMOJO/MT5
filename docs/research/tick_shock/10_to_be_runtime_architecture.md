# Step 10 runtime architecture

## Runtime flow

```text
OnTick / OnTimer
  -> TSMt5CopyInfoTicks
  -> TickShockPendingRepository
       append -> chronological sort -> strict global watermark release
  -> per-symbol TickShockGridRuntime + TickShockRingState
       last real quote -> fixed boundary -> detector samples
  -> baseline/histogram production core
       readiness -> percentile/median/MAD/noise floor
  -> detector metric core
       exact anchors -> move/Z/efficiency/intensity/spread ratios -> six gates
  -> TickShockEventEngineContext
       dedup -> event slot -> symbol cluster -> market cluster
  -> existing state machine and four-scenario grid
  -> existing shadow execution/CSV serializer
```

MT5 access stays in `TickShockMt5Adapter.mqh`. File serialization stays in the
existing serializer/EA wiring. State and calculation modules accept explicit
config/context/result objects and are callable with synthetic input.

## State ownership

| State | Owner | Reset | Mutation |
|---|---|---|---|
| tick/grid/sample cursors | per-symbol `TickShockRingState` | symbol init | reserve/drop helpers |
| latest quote/next boundary | per-symbol `TickShockGridRuntime` | symbol init | observe/advance helpers |
| baseline histogram/cache | per-symbol context | symbol init/rebuild | rolling add/remove and baseline core |
| detector counters | per-symbol+detector context | symbol init | result observer |
| event keys/allocation/clusters | `g_event_engine` context | `OnInit` | register/write/release |
| pending ticks/merge diagnostics | `g_pending_repository` context | `OnInit` | collect/sort/release/process |
| events/scenarios | bounded EA event records | allocation/release | existing state/scenario engine |

## Preserved clocks and ordering

- event time remains the original tick/grid time.
- processing time remains the dispatcher-visible recognition time.
- the global watermark is still the minimum of all six symbol frontiers.
- only ticks strictly older than the watermark are released.
- a same-symbol/same-`time_msc` group is never split; its final quote closes the
  grid boundary.
- entry eligibility, signal processing and scenario outcome semantics are not
  changed in Step 10.

## Baseline capacities

The compile-time physical cap is 3,612. With 15 minutes plus 2,000ms exclusion,
logical capacities remain 3,610 / 1,806 / 904 for 250/500/1,000ms. The generic
ring cursor does not allocate storage or alter retention; the EA allocates the
same arrays as before.

## Commission boundary

Production calls `TSMt5CommissionResult`, which invokes the existing one-lot
`OrderCalcProfit` adapter then the shared deterministic result builder. The
builder exposes calculation success, one-lot SL loss, commissionR, netR and
application count. A failed calculation continues to produce the pre-existing
zero-commission scenario behavior; this step does not change configured
commission (`0.0`) or CSV schema.

## No shortcuts

No test flag or synthetic shortcut exists in the research EA. Harnesses build
explicit inputs and call the same production facade. The expected CSV remains
an independent comparison oracle and is never generated by production code.
